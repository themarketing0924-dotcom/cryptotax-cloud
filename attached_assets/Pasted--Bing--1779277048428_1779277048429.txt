## **❌ 문제 1 — 빙 메타 인증 태그가 주석처리된 채로 방치**

소스 코드를 직접 보면 이렇게 되어 있습니다:

```html
<!-- 빙 웹마스터: https://www.bing.com/webmasters 에서 인증 코드 발급 후 아래 주석 해제 -->
<!-- <meta name="msvalidate.01" content="" /> -->
```

빙 웹마스터 대시보드에서는 이미 색인이 되고 있는데, **HTML 소스에는 빙 인증 메타태그가 아직 주석처리**된 상태입니다. 이게 어떻게 된 거냐면, 빙은 DNS 인증 또는 XML 파일 업로드 방식으로도 인증이 가능해서 메타태그 없이도 동작은 하지만, **메타태그 방식이 가장 안정적**이고 인증이 깨질 리스크가 없습니다. 지금은 다른 방법으로 인증된 상태일 가능성이 높으며, 메타태그는 비어있는(`content=""`) 채로 주석 처리되어 있어서 실제 인증값이 없습니다.

**즉시 조치:** 빙 웹마스터 → 설정 → 소유권 인증 → 메타태그 방식의 실제 코드를 복사해서 주석을 해제하고 `content=""` 안에 정확한 값을 넣어야 합니다.

## **❌ 문제 2 — JSON-LD가 `WebSite` 1개뿐, 리치 결과 기회 완전히 낭비 중**

빙이 "1개의 마크업 유형이 있습니다 — JSON-LD"라고 표시한 건 경고는 아니지만, **기회를 놓치고 있다는 신호**입니다. 현재 메인 페이지의 JSON-LD는 이것이 전부입니다:

```json
{
  "@type": "WebSite",
  "name": "CryptoTax.cloud",
  "potentialAction": { "@type": "SearchAction" }
}
```

빙과 구글 모두 아래 Schema가 추가되면 **검색결과에서 리치 스니펫으로 훨씬 크게 노출**됩니다:

```json
// 추가해야 할 Schema ①: FAQ (검색결과에 질문/답변 펼쳐서 노출)
{
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "코인 세금은 언제부터 내야 하나요?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "2027년 1월 1일부터 가상자산 양도소득세가 부과됩니다."
      }
    }
    // ... 8개 FAQ 전부 추가
  ]
}
```

```json
// 추가해야 할 Schema ②: WebApplication (계산기 도구 설명)
{
  "@type": "WebApplication",
  "name": "코인 세금 계산기",
  "applicationCategory": "FinanceApplication",
  "operatingSystem": "웹 브라우저",
  "offers": {
    "@type": "Offer",
    "price": "0",
    "priceCurrency": "KRW"
  }
}
```

## **❌ 문제 3 — IndexNow 미활용 (빙 전용 초고속 색인 기능)**

빙 웹마스터 좌측 메뉴에 **IndexNow** 항목이 있는 걸 확인하셨나요? IndexNow는 콘텐츠를 발행하는 즉시 빙(그리고 Yandex)에 URL을 자동으로 푸시해서 **수분 내 색인**이 가능한 기능입니다. 현재 새 블로그 글을 올려도 빙이 크롤링하기까지 며칠~수주가 걸릴 수 있는데, IndexNow를 설정하면 이 대기 시간을 사실상 제로로 만들 수 있습니다.

**즉시 조치:** 빙 웹마스터 → IndexNow → API 키 발급 → `https://cryptotax.cloud/[키값].txt` 파일 업로드 → 새 글 발행 시 자동으로 IndexNow API 호출하도록 설정
