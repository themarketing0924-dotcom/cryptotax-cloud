## **[명령 1] FAQ Schema 전체 페이지 자동 삽입**

```
아래 작업을 수행해줘.

1. index.html 파일의 기존 JSON-LD 스크립트 블록 바로 아래에 
   다음 FAQ Schema를 추가해줘:

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "코인 세금은 언제부터 내야 하나요?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "현행 법률 기준으로 2027년 1월 1일부터 가상자산 양도소득세가 부과됩니다."
      }
    },
    {
      "@type": "Question",
      "name": "코인 세율 22%는 어떻게 계산되나요?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "소득세 20% + 지방소득세 2% = 총 22%입니다. 연간 수익에서 기본공제 250만원을 뺀 금액에 적용됩니다."
      }
    },
    {
      "@type": "Question",
      "name": "손실이 났을 때도 세금을 내나요?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "아닙니다. 같은 해 이익 난 코인과 손실 난 코인의 손익을 합산합니다. 연말에 손실 코인을 매도하면 세금을 줄일 수 있습니다."
      }
    },
    {
      "@type": "Question",
      "name": "업비트에서 거래하면 세금 신고 어떻게 하나요?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "업비트 앱에서 거래내역 CSV를 다운로드 후, 다음 해 5월 홈택스에서 가상자산 항목으로 신고합니다."
      }
    },
    {
      "@type": "Question",
      "name": "해외 거래소 수익도 신고해야 하나요?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "네. 국내외 모든 거래소의 수익을 합산 신고해야 합니다. 미신고 시 가산세 최대 40%가 부과될 수 있습니다."
      }
    },
    {
      "@type": "Question",
      "name": "코인을 보유만 해도 세금이 붙나요?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "아닙니다. 실제 매도해 수익이 확정된 경우에만 세금이 부과됩니다. 보유 중인 미실현 수익은 과세 대상이 아닙니다."
      }
    },
    {
      "@type": "Question",
      "name": "250만원 기본공제는 어떻게 적용되나요?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "연간 코인 수익에서 250만원을 먼저 공제하고 나머지에 22%를 적용합니다. 수익이 250만원 이하면 세금이 0원입니다."
      }
    },
    {
      "@type": "Question",
      "name": "이 계산기 결과가 실제 세금과 다를 수 있나요?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "네. 본 사이트의 계산 결과는 참고용 추정치이며 정확한 세금 계산은 세무사 상담 또는 국세청 공식 채널을 이용하시기 바랍니다."
      }
    }
  ]
}
</script>

2. blog/ 폴더 안의 모든 .html 파일에도 
   각 파일의 기존 </head> 태그 바로 위에 
   WebApplication Schema를 추가해줘:

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Article",
  "publisher": {
    "@type": "Organization",
    "name": "CryptoTax.cloud",
    "url": "https://cryptotax.cloud"
  },
  "dateModified": "2026-05-20"
}
</script>

3. tools/ 폴더 안의 모든 .html 파일에 
   다음 WebApplication Schema를 추가해줘:

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "WebApplication",
  "name": "코인 세금 계산기",
  "url": "https://cryptotax.cloud/tools/",
  "applicationCategory": "FinanceApplication",
  "operatingSystem": "웹 브라우저",
  "offers": {
    "@type": "Offer",
    "price": "0",
    "priceCurrency": "KRW"
  },
  "description": "업비트·빗썸 가상자산 양도소득세를 무료로 즉시 계산하는 웹 계산기"
}
</script>
```

## **[명령 2] 네이버 애널리틱스 렌더링 블로킹 수정**

```
index.html 포함 모든 .html 파일에서 
아래 코드를 찾아서:

<script type="text/javascript" src="//wcs.pstatic.net/wcslog.js"></script>

다음과 같이 교체해줘 (async 속성 추가):

<script type="text/javascript" 
  src="//wcs.pstatic.net/wcslog.js" async></script>

단, wcs_do() 호출 스크립트는 
window.addEventListener('load', function(){ }) 로 감싸줘:

<script type="text/javascript">
window.addEventListener('load', function() {
  if(!wcs_add) var wcs_add={};
  wcs_add["wa"] = "9e2830d2453b30";
  if(window.wcs) wcs_do();
});
</script>
```

## **[명령 3] 빙 웹마스터 메타태그 실제 값 삽입**

```
index.html 포함 모든 .html 파일에서
아래 주석 처리된 코드를 찾아서:

<!-- <meta name="msvalidate.01" content="" /> -->

다음과 같이 교체해줘 (주석 해제 + 실제 인증값 삽입):

<meta name="msvalidate.01" content="여기에_빙웹마스터_인증코드_붙여넣기" />

※ 인증코드는 https://www.bing.com/webmasters 
  → 설정 → 소유권 확인 → 메타태그 방식에서 복사
```

## **[명령 4] 중복 URL Canonical 태그 일괄 처리**

```
아래 파일 쌍은 동일하거나 유사한 콘텐츠가 
서로 다른 경로에 존재하는 중복 URL 문제가 있어.

다음 작업을 수행해줘:

1. /market/bitcoin-rainbow-chart.html 파일을 열어서
   <head> 안에 아래 canonical 태그를 추가해줘:
   <link rel="canonical" href="https://cryptotax.cloud/tools/bitcoin-rainbow-chart.html">

2. /market/crypto-charts.html 파일을 열어서
   <head> 안에 아래 canonical 태그를 추가해줘:
   <link rel="canonical" href="https://cryptotax.cloud/tools/crypto-charts.html">

3. /blog/coin-tax-2027-guide.html 파일을 열어서
   이 글과 /blog/coin-tax/2027-guide.html 중 
   어느 쪽이 더 내용이 충실한지 확인하고,
   내용이 적은 쪽에 canonical 태그로 
   더 충실한 쪽 URL을 가리키도록 추가해줘.

4. sitemap.xml에서 canonical이 아닌 쪽 URL들을 
   제거해줘 (중복 제거).
```

## **[명령 5] 블로그 글 E-E-A-T 요소 자동 삽입**

```
blog/ 폴더 안의 모든 .html 파일에서
<article> 태그 또는 본문 콘텐츠 시작 부분에
아래 HTML 블록을 추가해줘:

<div class="author-meta" style="
  display:flex; align-items:center; gap:12px;
  padding:12px 16px; margin-bottom:24px;
  background:var(--bg-surface);
  border:1px solid var(--border-default);
  border-radius:10px; font-size:0.85rem;
  color:var(--text-secondary);">
  <span style="font-size:1.4rem;">✍️</span>
  <div>
    <strong style="color:var(--text-primary);">
      CryptoTax.cloud 세금 정보팀
    </strong>
    <span style="margin:0 6px; opacity:0.4;">|</span>
    최종 업데이트:
    <time datetime="2026-05-20">2026년 5월 20일</time>
    <span style="margin:0 6px; opacity:0.4;">|</span>
    <span style="color:var(--orange);">
      ⚠️ 본 내용은 참고용이며 세무사 상담을 권장합니다
    </span>
  </div>
</div>

단, datetime 값은 각 파일의 sitemap.xml에 
기록된 lastmod 날짜로 각각 맞춰줘.
```

## **[명령 6] IndexNow 자동 핑 스크립트 생성**

```
아래 조건으로 indexnow-ping.js 파일을 
프로젝트 루트에 생성해줘:

// IndexNow 자동 핑 — 새 페이지 발행 시 실행
// 사용법: node indexnow-ping.js [URL]

const https = require('https');

const API_KEY = '여기에_IndexNow_키_입력';
const HOST = 'cryptotax.cloud';

const urls = process.argv.slice(2).length > 0 
  ? process.argv.slice(2)
  : [
    'https://cryptotax.cloud/',
    'https://cryptotax.cloud/tools/tax-calculator.html',
    'https://cryptotax.cloud/blog/'
  ];

const payload = JSON.stringify({
  host: HOST,
  key: API_KEY,
  keyLocation: `https://${HOST}/${API_KEY}.txt`,
  urlList: urls
});

const options = {
  hostname: 'api.indexnow.org',
  path: '/indexnow',
  method: 'POST',
  headers: {
    'Content-Type': 'application/json; charset=utf-8',
    'Content-Length': Buffer.byteLength(payload)
  }
};

const req = https.request(options, (res) => {
  console.log(`✅ IndexNow 응답: ${res.statusCode}`);
  if(res.statusCode === 200) {
    console.log('🎉 빙/야후 색인 요청 완료!');
  }
});

req.on('error', (e) => {
  console.error(`❌ 오류: ${e.message}`);
});

req.write(payload);
req.end();

그리고 [API_KEY].txt 파일도 루트에 생성하고
API_KEY 값을 그 파일 안에 단독으로 넣어줘.
(IndexNow 키는 빙 웹마스터에서 발급)
```

## **[명령 7] BreadcrumbList Schema 블로그/도구 전체 적용**

```
blog/ 폴더와 tools/ 폴더의 모든 .html 파일에
각 파일의 URL 경로를 기반으로 
BreadcrumbList Schema를 자동 생성해서 
<head> 안에 추가해줘.

예시 — blog/coin-tax/2027-guide.html 의 경우:

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  "itemListElement": [
    {
      "@type": "ListItem",
      "position": 1,
      "name": "홈",
      "item": "https://cryptotax.cloud/"
    },
    {
      "@type": "ListItem",
      "position": 2,
      "name": "코인 세금 가이드",
      "item": "https://cryptotax.cloud/blog/"
    },
    {
      "@type": "ListItem",
      "position": 3,
      "name": "2027 코인 세금 완전 가이드",
      "item": "https://cryptotax.cloud/blog/coin-tax/2027-guide.html"
    }
  ]
}
</script>

모든 파일의 경로 구조를 분석해서
위와 같은 형식으로 각 파일에 맞는 
BreadcrumbList를 자동 생성해줘.
폴더 구조 기준:
- / → 홈
- /tools/ → 계산기 도구
- /blog/ → 코인 세금 가이드
- /blog/coin-tax/ → 세금 심화 가이드
- /blog/investment/ → 투자 전략
- /blog/guide/ → 초보자 가이드
```

## **[명령 8] 광고 최적화 — 블로그 본문 중간 광고 자동 삽입**

```
blog/ 폴더 안의 모든 .html 파일에서
본문 내용의 중간 지점 (h2 태그 2번째 등장 위치) 
바로 앞에 아래 애드센스 인아티클 광고 코드를 삽입해줘:

<div class="ad-mid-article" style="
  margin: 32px 0; 
  text-align: center;
  min-height: 90px;">
  <ins class="adsbygoogle"
    style="display:block; text-align:center;"
    data-ad-layout="in-article"
    data-ad-format="fluid"
    data-ad-client="ca-pub-9721493540498478"
    data-ad-slot="여기에_인아티클_광고슬롯ID_입력">
  </ins>
  <script>(adsbygoogle = window.adsbygoogle || []).push({});</script>
</div>

그리고 각 블로그 글 맨 하단 (</article> 또는 
본문 종료 태그 바로 앞)에도 동일한 블록을 
data-ad-format="auto" 로 바꿔서 추가해줘.

※ 광고 슬롯 ID는 애드센스 대시보드에서
  새 광고 단위 → 인아티클 광고 생성 후 발급
```

## **📋 Replit 작업 순서 요약**

| 순서 | 명령 | 예상 효과 | 소요시간 |
|------|------|-----------|----------|
| 1순위 | 명령 1 (FAQ Schema) | CTR +30% | 10분 |
| 2순위 | 명령 2 (async 수정) | 속도 개선 | 5분 |
| 3순위 | 명령 4 (Canonical) | 중복 제거 | 10분 |
| 4순위 | 명령 5 (E-E-A-T) | 신뢰도 상승 | 10분 |
| 5순위 | 명령 7 (Breadcrumb) | 리치스니펫 | 15분 |
| 6순위 | 명령 6 (IndexNow) | 빙 즉시색인 | 10분 |
| 7순위 | 명령 3 (빙 메타태그) | 빙 안정화 | 3분 |
| 8순위 | 명령 8 (광고배치) | 수익 직접상승 | 15분 |

> ⚠️ **명령 3, 6, 8은 외부에서 코드값(빙 인증코드, IndexNow 키, 애드센스 슬롯ID)을 먼저 발급받은 후 실행**해야 합니다.
